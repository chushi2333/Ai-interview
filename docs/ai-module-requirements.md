# AI 模块需求分析

## 业务定位

AI 模块不做单纯的通用聊天，而是围绕面试刷题场景提供学习辅助。

核心目标：

- 帮用户理解题目和题解
- 根据用户回答做反馈和补充
- 基于用户学习活动生成更合适的练习内容
- 后续逐步学习和接入 LangChain4j 的 Agent、Tool Calling、RAG 能力

## 不做什么

- 不做一个独立的通用 AI 聊天页
- 不让 AI 脱离题库和学习行为随意回答
- 不在第一版直接做复杂推荐系统
- 不在第一版直接做完整 RAG 和长期记忆
- 不让 AI 自动修改题目、题解、用户数据

## 产品形态

AI 能力应该拆成多个学习场景，而不是只有模拟面试。

### AI 题解助教

入口：题目详情页。

能力：

- 用大白话解释当前题
- 总结面试回答模板
- 提炼回答重点
- 生成面试官追问
- 结合用户自测结果解释错因
- 帮用户把回答改成更适合面试的表达

第一版可以不依赖 RAG，因为当前题目的 `title`、`content`、`answer` 已经是直接上下文。

### AI 模拟面试

入口：

- 题目详情页
- 题库页
- 错题本
- 学习档案

能力：

- 围绕当前题目继续追问
- 围绕一个题库抽题面试
- 围绕错题做查漏补缺
- 围绕最近学习记录生成一轮面试

模拟面试不是固定问答。用户可以在面试过程中插话追问，例如：

- 我没听懂
- 举个例子
- 给我一个标准答案
- 我这样回答可以吗
- 这个和另一个概念有什么区别

AI 需要判断用户消息类型：

- 如果是回答，给评价、指出缺漏、补充参考答案、继续追问
- 如果是追问，先解释，再拉回当前面试主题
- 如果用户不知道，给提示或降低问题难度

### AI 个性化出题

入口：

- 首页
- 学习档案
- 错题本

能力：

- 根据最近浏览、收藏、错题、自测记录生成练习方向
- 从题库和题解中检索相关题目
- 选择适合当前用户的题目并说明原因

这一部分适合使用 RAG。

原因：

- 用户学习活动只能说明“用户可能薄弱在哪里”
- 真正选题需要从题库、题解、资料中检索候选内容
- AI 再根据候选内容做筛选和解释

### AI 学习复盘

入口：学习档案。

能力：

- 总结最近 7 天学习情况
- 分析薄弱知识点
- 总结高频错题类型
- 给下一步复习建议
- 生成小的学习计划

这一部分依赖学习行为数据，适合放在 RAG 和个性化出题之后。

## MVP 建议

第一版只做 AI 题解助教。

目标是先打通：

```text
题目详情页 -> AI 助教按钮 -> 后端拿当前题目上下文 -> LangChain4j 调模型 -> 返回结构化回答
```

建议接口：

```http
POST /api/ai/question/{questionId}/assist
```

请求：

```json
{
  "type": "simple_explain",
  "user_input": "我不理解缓存击穿"
}
```

`type` 可选值：

- `simple_explain`：大白话解释
- `interview_answer`：面试回答模板
- `key_points`：提炼重点
- `follow_up_questions`：生成追问
- `wrong_answer_explain`：错因解释

返回：

```json
{
  "content": "..."
}
```

## LangChain4j 接入路线

### 第一阶段：模型调用

目标：

- 接入 LangChain4j
- 配置 ChatModel
- 使用 AI Service 封装题解助教
- 完成同步返回

不做：

- 不做流式输出
- 不做 RAG
- 不做 Tool Calling
- 不做多轮持久化会话

### 第二阶段：模拟面试会话

目标：

- 增加面试 Session
- 保存本轮面试消息
- AI 根据上下文继续追问
- 用户可以在场景内自由追问

建议接口：

```http
POST /api/ai/interview/session
POST /api/ai/interview/session/{sessionId}/message
```

### 第三阶段：Tool Calling

目标：让 AI 可以调用后端已有业务能力。

候选工具：

- 查询当前题目
- 查询题库下题目
- 查询用户最近学习记录
- 查询错题本
- 查询收藏题目

这一步是 Agent 的基础。

### 第四阶段：RAG

目标：让 AI 基于题库、题解、外部整理资料检索后回答或选题。

需要补的能力：

- 文档切分
- Embedding
- 向量存储
- 相似度检索
- 检索结果拼 prompt
- 索引重建脚本

RAG 优先服务于：

- 个性化出题
- 题库范围模拟面试
- 学习复盘

## 数据来源

现有可用数据：

- 题目 `question`
- 题库 `question_bank`
- 题库题目关系 `question_bank_question`
- 题目查看记录 `question_view_record`
- 自测记录 / 练习记录
- 错题本
- 收藏题目
- 签到记录

第一版只需要题目上下文。

后续个性化能力再逐步接入学习行为数据。

## 工程原则

- API Key 只放环境变量，不写入代码和 Git
- AI 功能先独立，不影响现有刷题主流程
- 第一版同步返回，后续再做 SSE 流式输出
- Prompt 要明确限制场景，避免回答偏题
- AI 输出只作为学习建议，不直接修改业务数据
- 先做可验证的小闭环，再升级 Agent 和 RAG

## 推荐实现顺序

1. AI 题解助教
2. 模拟面试会话
3. Tool Calling
4. RAG 题目检索
5. AI 个性化出题
6. AI 学习复盘
